call/0053: the spine copy is re-derived, not asserted

  • Status: accepted
  • Scope: the methodology spine and how it reaches this repository and every adopter; what the spine mechanically is, how a project's copy is produced, and what re-verifies it on every gate run
  • Date: 2026-08-02
  • Ratified: 2026-08-02 by the operator, who ruled on all three prerequisites this record had left open: guard the spine at the commit hook rather than only in CI, rewrite the spine to address the adopter who holds it, and perform the migration in full. Those rulings are folded into the text below rather than left as commentary. Entered at proposed per call/0052, because the tool treats accepted as a credential and an agent does not issue itself one.
  • Refines: call/0004, whose copy-at-version outcome stands unchanged. This decision supplies the enforcement call/0004 never had.

Context and problem

call/0004 chose copy-at-version on 2026-06-14: the template authors the spine, every project holds a copy at the revision it adopted, and "the copy is inline and acted-on (not a fragile pointer), so governance stays strong locally." It named this repository adopter zero, not a special case.

Measured on 2026-08-02, against the canonical host-lint artifact rather than a PATH copy:

this repotemplatebyte-identical
CLAUDE.md, non-trivial lines778140
STRUCTURE.md, non-trivial lines15840

Not one line. git log --follow puts this repository's CLAUDE.md between 128 and 137 lines continuously from 2026-06-06 to today, while the template's is 1001. The copy was never made. call/0004 was ratified, later promoted into the spine itself, and was not true for a single commit in seven weeks.

Nothing detected it because nothing re-derives it. The spine arrives by an instruction to an agent, which is the whole of the mechanism: the adopt skill says "Copy the template's CLAUDE.md in unchanged at the chosen revision", and the upgrade skill's re-apply instruction reads, in full, "Re-apply the spine doc changes across the span; leave project-specifics alone." host-lifecycle scaffold writes three empty rooms and the stamp; it does not touch either file.

That is the asymmetry. An artifact reproduces byte-for-byte from its pin or the build lane fails. A rung is discharged by re-derivation, not by name-presence. A task's inputs are fingerprinted so a done goes stale when they drift. Every phase carries a closed recheck = because evidence is never self-asserted. The methodology re-derives everything except itself.

The cost is not abstract. The upgrade ledger carries 51 entries, 32 with a verify, and 26 of those 32 test a file under host-template/, a shape the ledger's own header forbids and cannot amend, because it is "a post-condition of the command's own precondition." Those entries are an author reaching for something checkable on the adopter's side, finding nothing there, and grepping the template instead. The ledger is not badly written; it is carrying a load that belongs to a mechanism nobody built.

What the stamp claims, and what it can show

.host records baseline = "ff04a94", a ledger position. It carries no revision for the copy and no hash of it. So the stamp asserts that this project holds the spine at a revision, and there is no artifact against which that assertion could ever be checked. A claim with no possible referent cannot drift, because it was never anchored; it can only be discovered to have been empty.

Decision

The spine is a file set, not a region, and a project's copy is a rendered artifact re-derived on every gate run.

  1. The spine is defined by extension, not by description. It is the byte content of host-template/CLAUDE.md and host-template/STRUCTURE.md, whole, at the revision .host records. Not a subset, not a paraphrase, not the four principles plus two disciplines. A boundary drawn by description is a boundary two readers draw differently.

  2. A project authors CLAUDE.project.md and nothing else. Its root CLAUDE.md and STRUCTURE.md are generated by host-lifecycle spine --render: the spine verbatim, then the project's fragment. The boundary is a file boundary, because a marked region inside one merged manual is exactly what a case-(b) adoption cannot produce cleanly, and a boundary an agent places by hand is a boundary that is placed wrong.

  3. spine --check re-renders and compares byte-for-byte, the shape --verify-build already uses. It is a clause of the verify phase's recheck, so drift re-opens the receipt and stops a release at its first step.

  4. .host gains spine = <sha256> of the rendered file. The stamp then names bytes rather than a label, and a cold read can establish what text the project actually holds.

The anti-drift clauses

call/0004 failed as a rule that was written down. These exist so this one cannot fail the same way.

  1. No waiver, no exemption, no escape key. There is no spine-waiver, no ignore entry that reaches the rendered files, and no advisory tier. call/0046 retired an unimplemented escape rather than implement it; this ships with none to retire.

  2. The clause is protected core. skippable = false, as verify already is. A skip receipt is refused outright rather than accepted with a citation.

  3. A check that cannot run is red. Absent template, unreadable file, unknown subcommand: each fails closed and names the command that fixes it. A verdict over a corpus with a hole in it is a claim the run cannot make.

  4. The check names the binary that answered. spine --check prints the resolved executable path and version. On 2026-08-02 a stale host-lint on PATH produced a false defect report that nearly triggered a release cascade, and nothing in the tree could have caught it; a re-derivation whose deriver is unidentified is not a re-derivation.

  5. The rule lives in the spine. A rule about what the spine is belongs in the file set it governs, so every adopter holds it verbatim and no project can soften it locally. This decision is the authoring record; the rule itself ships in the template.

  6. The fragment is held against becoming a second source. A project that restates spine doctrine in its own words rebuilds the fork this exists to close, which is precisely how this repository arrived at 0 shared lines. reconcile already requires pointing over paraphrasing; it is pointed at the fragment, and its coverage bites there.

  7. The rendered files carry zero lint findings, at the flagging and the warning tier both. Measured today, the spine as adopter root content is already rc=0 on the naming and prose lanes and rc=0 on references. This repository's own manual is rc=3, on a paragraph the render deletes as subsumed doctrine.

  8. The spine is guarded where it is authored, by commit hook. The template repository carries the same pre-commit and commit-msg hooks every other repository under this methodology carries, so spine text that would redden an adopter cannot be committed upstream in the first place. On 2026-08-02 its hooks directory was empty: the one repository whose every line ships verbatim to every adopter was the one repository with no gate on its own commits, and --install-hooks reaches the host and its materialized worktrees but not a submodule. A lane in CI is the second line, not the first, because CI reports after the text is already recorded.

Consequences

This repository pays first and most. It absorbs 1001 verbatim lines; its 137 become the fragment; its four principles are replaced by the template's wording. That is the host↔template sole-source reconciliation its own CLAUDE.md defers as "a deferred and deliberate duplication," performed rather than deferred.

Most of the ledger stops being needed. A prose-only entry has nothing to ask of an adopter once regeneration is the application. What remains is structural: convert the submodule, untrack the symlink, wire a lane. That is what the ledger's header says it is for.

CLAUDE.md becomes generated and tracked, a category this methodology has not had. The existing rule against tracking generated artifacts governs paths that may be absent; the manual never is. It is the lockfile pattern, and it is checked the way a lockfile is checked: regenerate, compare.

A new failure mode is created and must be accepted knowingly. Spine prose that trips a lint rule reddens every adopter's gate on text they cannot edit, and a LEXICON entry is unsound for inherited text by call/0051. So the spine must hold clean under the rules it ships with no declaration anywhere. Today nothing guarantees that: the template's hooks directory is empty, its CI runs one lane (host-lifecycle prose .), and this repository excludes host-template/ from its naming audit as "audited upstream, not host content." Clause 12 closes it at the commit, and the naming lane joins the template's CI behind that.

The spine is currently written for the wrong reader. It opens "You are working in a template. A real project replaces the example personas with its own", which is false in every rendered adopter file. The render is therefore not concatenation, and rewriting the spine to address the adopter who will hold it is a prerequisite to the mechanism rather than a detail of it.

What this does not decide

  • Whether STRUCTURE.md takes the same fragment treatment as CLAUDE.md or is spine-only. It is rendered either way; only the fragment slot is open.
  • How reconcile's coverage check is scoped to the fragment (clause 10) in mechanical terms.
  • The disposition of the 51 existing ledger entries once regeneration carries the prose half. They are append-only and stay; whether a new entry supersedes a class of them is a separate decision.
