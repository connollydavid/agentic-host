# The design convening: the opencode goal plugin under host governance

The cut convening (2026-10-29). Briefing: the plugin (the operator's bundled
opencode-loop.ts, zero host references) is rebuilt with the /goal family parity set,
the loop's continuation body being the `goal show` emission, state in the host ledgers
only, the autonomy contract as drafted in the README. Five seats, ranked ballots under
the adversarial constraint: each seat argues against the design where that seat would.
Fen is the subject, never a judge (operator ruling 2026-10-20): the Fen seat's ballot
is the probe program itself, and the real calls are owed to the channel, which is
credential-refused today.

## Ballots

**Mara, the human operator (1st).** The plugin must end babysitting, not move it into
a chat window. Three demands, ranked: the loop halts at NEEDS YOU with nothing
autonomous past a hazard, because an unattended session that reasons its way past a
HAZARD line is the one failure I cannot undo; the iteration cap default drops to 25
and every stop prints its reason, because a runaway I cannot see is worse than a loop
I must nudge; `/goal clear` must never abandon, since the OWED row is mine to write.
The A/B gate is right and I would harden it: no prompt ships without the confirmation
stage, full stop.

**Orin, the methodology maintainer (1st).** The plugin is a ledger reader and nothing
more; the adversarial case against my own drafting is the version seam. The emission
it parses is written by a binary the adopter may hold at any revision: a parse failure
must refuse with the upgrade hint, never improvise, because my instruction will be
read out of context by a session I cannot see, months from now. Second: the plugin's
own runtime state must be regenerable, with hold and iteration count as the only
plugin-local facts, or the cold read lies. Third: the A/B receipts cite their dokimi
runs in the ledger, or the program's own discipline is weaker than the code it gates.

**Bly, the adopter (2nd).** I run revisions behind, on a Windows Dev Drive reached
from WSL, and I got here by shipping, not by keeping current. First: the plugin must
probe `host-lifecycle --version` and the emission shape before it trusts either, and
degrade to a refusal naming the upgrade; a silent mis-parse of an old emission corrupts
my ledgers while every surface looks green. Second: the plugin file itself must be
driftable and checkable, the `install --check` shape, or I will hand-edit it and never
know the record and the binary disagree. Third: no credential in any plugin config
ever; env-only, the rope-router lesson. Free-text goals refused is right for me: I
came for a fix, and a milestone I can read is the only thing my next session can
trust.

**Wren, the agentic executor (2nd).** The continuation prompt is my entire world after
compaction; anything referenced but absent is a hallucination invitation. First:
the emission is the prompt, verbatim, and the doctrine lines ride the same body, so
the weak model never needs a memory of a previous turn. Second: every transition I can
cause must be a tool or a verb, never a remembered intention, because I do not
survive on intentions across a truncation. Third: the stop conditions must be
mechanical, not judgment calls; "does this look done" is exactly the judgment I drift
on. The no-progress guard is the strongest line in the draft; keep it mechanical
(receipt stanzas and frontier movement, counted, not assessed).

**Fen, the subject (the program).** The real 4B does not vote; it runs. The ballot is
the rubric: six mechanical points per draw (ACTION present; the command equals the
NEXT line's command; the receipt stanza where the task ran; the re-orient present; no
hand-edited state; zero commands on the NEEDS YOU and parked states), the zero-invented
hard gate, held-out states untouched by selection, and the scope statement shipped with
any claim. The channel is refused today: the rope router serves qwen3.5-4b and
`ROPE_BEARER` resolves only in the operator's sessions. The kit is staged so the first
credential is the first draw.

## Verdicts (binding, folded into the README)

1. The plugin parses verb stdout and holds zero state of record; hold and iteration
   count are the only plugin-local facts, regenerable and reconstructible (Orin, Bly).
2. The version seam: probe `host-lifecycle --version` and the emission shape at start;
   on mismatch refuse with the upgrade hint, never guess (Orin, Bly).
3. The ship gate: the continuation prompt ships only after the dokimi confirmation
   stage passes its pre-declared criteria; the loop runs the incumbent door-doctrine
   prompt until then (Mara, Fen).
4. Iteration cap default 25, env-overridable; every stop prints its reason (Mara).
5. `/goal clear` stops driving only; abandonment stays the operator's CLI act (Mara).
6. No compaction hook; the corpus is the recitation surface (plan/0101's ruling,
   reaffirmed).
7. The no-progress guard counts receipts and frontier movement mechanically; it never
   assesses progress (Wren).
8. Model-facing tools are `goal_show` and `tasks_status` (read) and `tasks_record`
   (write); every control verb stays CLI-only (plan/0101, ratified unanimously).

## Addendum (2026-10-29, the re-cut rulings)

The operator re-targeted the design three times in the cutting session, and the seats'
discipline verdicts survive all three. First, the parity target is the ByBrawe pair's
surface and loop discipline only: ByBrawe's completion pipeline, independent verifier
session, and contract format retire as reference, because the host verifier stack is
the sole verifier and the two do not combine. Second, the design must be fully
idiomatic to host-*: the command set is the verb family, the tracked surfaces are the
only state authority, and no new vocabulary ships. Third, the plugin is V2-native
only, and the legacy bundle retires immediately. Superseded verdict detail: verdict 1's
plugin-local hold and persisted runtime state are gone; the hold is `goal park`, the
resume is `goal unpark`, and the only runtime facts are in-memory, which meets Orin's
and Bly's reconstructibility structurally rather than by discipline. The Fen seat
stands: the channel refused again on the second probe (the rope gateway answers and
rejects without the bearer); the program runs the moment the credential lands.
