Essentials <a class="header-anchor" href="#rule-essentials" aria-label="Permalink to &quot;Rule Essentials&quot;">​</a></h1><p>Now you have learnt the basic of ast-grep&#39;s pattern syntax and searching. Pattern is a handy feature for simple search. But it is not expressive enough for more complicated cases.</p><p>ast-grep provides a more sophisticated way to find your code: Rule.</p><p>Rules are like <a href="https://www.w3schools.com/cssref/css_selectors.php" target="_blank" rel="noreferrer">CSS selectors</a> that can compose together to filter AST nodes based on certain criteria.</p><h2 id="a-minimal-example" tabindex="-1">A Minimal Example <a class="header-anchor" href="#a-minimal-example" aria-label="Permalink to &quot;A Minimal Example&quot;">​</a></h2><p>A minimal ast-grep rule looks like this.</p><div class="language-yaml vp-adaptive-theme"><button title="Copy Code" class="copy"></button><span class="lang">yaml</span><pre class="shiki shiki-themes github-light github-dark vp-code" tabindex="0"><code><span class="line"><span style="--shiki-light:#22863A;--shiki-dark:#85E89D;">id</span><span style="--shiki-light:#24292E;--shiki-dark:#E1E4E8;">: </span><span style="--shiki-light:#032F62;--shiki-dark:#9ECBFF;">no-await-in-promise-all</span></span>
<span class="line"><span style="--shiki-light:#22863A;--shiki-dark:#85E89D;">language</span><span style="--shiki-light:#24292E;--shiki-dark:#E1E4E8;">: </span><span style="--shiki-light:#032F62;--shiki-dark:#9ECBFF;">TypeScript</span></span>
<span class="line"><span style="--shiki-light:#22863A;--shiki-dark:#85E89D;">rule</span><span style="--shiki-light:#24292E;--shiki-dark:#E1E4E8;">:</span></span>
<span class="line"><span style="--shiki-light:#22863A;--shiki-dark:#85E89D;">  pattern</span><span style="--shiki-light:#24292E;--shiki-dark:#E1E4E8;">: </span><span style="--shiki-light:#032F62;--shiki-dark:#9ECBFF;">Promise.all($A)</span></span>
<span class="line"><span style="--shiki-light:#22863A;--shiki-dark:#85E89D;">  has</span><span style="--shiki-light:#24292E;--shiki-dark:#E1E4E8;">:</span></span>
<span class="line"><span style="--shiki-light:#22863A;--shiki-dark:#85E89D;">    pattern</span><span style="--shiki-light:#24292E;--shiki-dark:#E1E4E8;">: </span><span style="--shiki-light:#032F62;--shiki-dark:#9ECBFF;">await $_</span></span>
<span class="line"><span style="--shiki-light:#22863A;--shiki-dark:#85E89D;">    stopBy</span><span style="--shiki-light:#24292E;--shiki-dark:#E1E4E8;">: </span><span style="--shiki-light:#032F62;--shiki-dark:#9ECBFF;">end</span></span></code></pre></div><p>The <em>TypeScript</em> rule, <em>no-await-in-promise-all</em>, will find <code>Promise.all</code> that <strong>has</strong> <code>await</code> expression in it.</p><p>It is <a href="https://github.com/hugo-vrijswijk/eslint-plugin-no-await-in-promise/" target="_blank" rel="noreferrer">suboptimal</a> because <code>Promise.all</code> will be called <a href="https://twitter.com/hd_nvim/status/1560108625460355073" target="_blank" rel="noreferrer">only after</a> the awaited Promise resolves first.</p><p>Let&#39;s walk through the main fields in this configuration.</p><ul><li><p><code>id</code> is a unique short string for the rule.</p></li><li><p><code>language</code> is the programming language that the rule is intended to check. It specifies what files will be checked against this rule, based on the file extensions. See the list of <a href="/reference/languages">supported languages</a>.</p></li><li><p><code>rule</code> is the most interesting part of ast-grep&#39;s configuration. It accepts a <a href="/reference/rule">rule object</a> and defines how the rule behaves and what code will be matched. You can learn how to write rule in the <a href="/guide/rule-config/atomic-rule">detailed guide</a>.</p></li></ul><h2 id="run-the-rule" tabindex="-1">Run the Rule <a class="header-anchor" href="#run-the-rule" aria-label="Permalink to &quot;Run the Rule&quot;">​</a></h2><p>There are several ways to run the rule. We will illustrate several ast-grep features here.</p><h3 id="ast-grep-scan-rule" tabindex="-1"><code>ast-grep scan --rule</code> <a class="header-anchor" href="#ast-grep-scan-rule" aria-label="Permalink to &quot;`ast-grep scan --rule`&quot;">​</a></h3><p>The <code>scan</code> subcommand of ast-grep CLI can run one rule at a time.</p><p>To do so, you need to save the rule above in a file on the disk, say <code>no-await-in-promise-all.yml</code>. Think about how selectors in CSS works can help you understand the rule object!</p><div class="tip custom-block"><p class="custom-block-title">TIP</p><p>Don&#39;t be daunted! The root rule will have <em>only one</em> AST node in one match. The matched node is called target node. During scanning and rewriting, ast-grep will produce multiple matches to report all AST nodes that satisfies the <code>rule</code> condition as matched instances.</p><p>Though one rule match only have one AST node as matched, we can have more auxiliary nodes to display context or to perform rewrite. We will cover how rules work in details in the next page.</p><p>But for a quick primer, a rule can have a pattern and we can extract meta variables from the matched node.</p><p>For example, the rule below will match the <code>console.log(&#39;Hello World&#39;)</code>.</p><div class="language-yaml vp-adaptive-theme"><button title="Copy Code" class="copy"></button><span class="lang">yaml</span><pre class="shiki shiki-themes github-light github-dark vp-code" tabindex="0"><code><span class="line"><span style="--shiki-light:#22863A;--shiki-dark:#85E89D;">rule</span><span style="--shiki-light:#24292E;--shiki-dark:#E1E4E8;">:</span></span>
<span class="line"><span style="--shiki-light:#22863A;--shiki-dark:#85E89D;">  pattern</span><span style="--shiki-light:#24292E;--shiki-dark:#E1E4E8;">: </span><span style="--shiki-light:#032F62;--shiki-dark:#9ECBFF;">console.log($GREET)</span></span></code></pre></div><p>And we can get <code>$GREET</code> set to <code>&#39;Hello World&#39;</code>.</p><h2 id="language-specifies-rule-interpretation" tabindex="-1"><code>language</code> specifies <code>rule</code> interpretation <a class="header-anchor" href="#language-specifies-rule-interpretation" aria-label="Permalink to &quot;`language` specifies `rule` interpretation&quot;">​</a></h2><p>The <code>language</code> field in the rule configuration will specify how the rule is interpreted. For example, with <code>language: TypeScript</code>, the rule pattern <code>&#39;hello world&#39;</code> is parsed as TypeScript string literal.
