# Crate os\_str\_bytes Copy item path

[Source](../src/os_str_bytes/lib.rs.html#1-937)

Expand description

This crate provides additional functionality for [`OsStr`](https://doc.rust-lang.org/nightly/std/ffi/os_str/struct.OsStr.html "struct std::ffi::os_str::OsStr") and [`OsString`](https://doc.rust-lang.org/nightly/std/ffi/os_str/struct.OsString.html "struct std::ffi::os_str::OsString"), without resorting to panics or corruption for invalid UTF-8. Thus, familiar methods from [`str`](https://doc.rust-lang.org/nightly/std/primitive.str.html "primitive str") and [`String`](https://doc.rust-lang.org/nightly/alloc/string/struct.String.html "struct alloc::string::String") can be used.

## [§](#usage)Usage

The most important trait included is [`OsStrBytesExt`](trait.OsStrBytesExt.html "trait os_str_bytes::OsStrBytesExt"), which provides methods analogous to those of [`str`](https://doc.rust-lang.org/nightly/std/primitive.str.html "primitive str") but for [`OsStr`](https://doc.rust-lang.org/nightly/std/ffi/os_str/struct.OsStr.html "struct std::ffi::os_str::OsStr"). These methods will never panic for invalid UTF-8 in a platform string, so they can be used to manipulate [`OsStr`](https://doc.rust-lang.org/nightly/std/ffi/os_str/struct.OsStr.html "struct std::ffi::os_str::OsStr") values with the same simplicity possible for [`str`](https://doc.rust-lang.org/nightly/std/primitive.str.html "primitive str").

Additionally, the following wrappers are provided. They are primarily legacy types from when this crate needed to perform more frequent encoding conversions. However, they may be useful for their trait implementations.

- [`RawOsStr`](struct.RawOsStr.html "struct os_str_bytes::RawOsStr") is a wrapper for [`OsStr`](https://doc.rust-lang.org/nightly/std/ffi/os_str/struct.OsStr.html "struct std::ffi::os_str::OsStr").

- [`RawOsString`](struct.RawOsString.html "struct os_str_bytes::RawOsString") is a wrapper for [`OsString`](https://doc.rust-lang.org/nightly/std/ffi/os_str/struct.OsString.html "struct std::ffi::os_str::OsString").

## [§](#user-input)User Input

Most methods in this crate should not be used to convert byte sequences that did not originate from [`OsStr`](https://doc.rust-lang.org/nightly/std/ffi/os_str/struct.OsStr.html "struct std::ffi::os_str::OsStr") or a related struct. The encoding used by this crate is an implementation detail, so it does not make sense to expose it to users.

For user input with an unknown encoding similar to UTF-8, use the following IO-safe methods, which avoid errors when [writing to streams on Windows](https://doc.rust-lang.org/std/io/struct.Stdout.html#note-windows-portability-considerations). These methods will not accept or return byte sequences that are invalid for input and output streams. Therefore, they can be used to convert between bytes strings exposed to users and platform strings.

- [`OsStrBytes::from_io_bytes`](trait.OsStrBytes.html#tymethod.from_io_bytes "associated function os_str_bytes::OsStrBytes::from_io_bytes")

- [`OsStrBytes::to_io_bytes`](trait.OsStrBytes.html#tymethod.to_io_bytes "method os_str_bytes::OsStrBytes::to_io_bytes")

- [`OsStrBytes::to_io_bytes_lossy`](trait.OsStrBytes.html#tymethod.to_io_bytes_lossy "method os_str_bytes::OsStrBytes::to_io_bytes_lossy")

- [`OsStringBytes::from_io_vec`](trait.OsStringBytes.html#tymethod.from_io_vec "associated function os_str_bytes::OsStringBytes::from_io_vec")

- [`OsStringBytes::into_io_vec`](trait.OsStringBytes.html#tymethod.into_io_vec "method os_str_bytes::OsStringBytes::into_io_vec")

- [`OsStringBytes::into_io_vec_lossy`](trait.OsStringBytes.html#tymethod.into_io_vec_lossy "method os_str_bytes::OsStringBytes::into_io_vec_lossy")

## [§](#implementation)Implementation

Some methods return [`Cow`](https://doc.rust-lang.org/nightly/alloc/borrow/enum.Cow.html "enum alloc::borrow::Cow") to account for platform differences. However, no guarantee is made that the same variant of that enum will always be returned for the same platform. Whichever can be constructed most efficiently will be returned.

All traits are [sealed](https://rust-lang.github.io/api-guidelines/future-proofing.html#c-sealed), meaning that they can only be implemented by this crate. Otherwise, backward compatibility would be more difficult to maintain for new features.

## [§](#encoding-conversions)Encoding Conversions

Methods provided by the “conversions” feature use an intentionally unspecified encoding. It may vary for different platforms, so defining it would run contrary to the goal of generic string handling. However, the following invariants will always be upheld:

- The encoding will be compatible with UTF-8. In particular, splitting an encoded byte sequence by a UTF-8–encoded character always produces other valid byte sequences. They can be re-encoded without error using [`RawOsString::into_os_string`](struct.RawOsString.html#method.into_os_string "method os_str_bytes::RawOsString::into_os_string") and similar methods.

- All characters valid in platform strings are representable. [`OsStr`](https://doc.rust-lang.org/nightly/std/ffi/os_str/struct.OsStr.html "struct std::ffi::os_str::OsStr") and [`OsString`](https://doc.rust-lang.org/nightly/std/ffi/os_str/struct.OsString.html "struct std::ffi::os_str::OsString") can always be losslessly reconstructed from extracted bytes.

Note that the chosen encoding may not match how [`OsStr`](https://doc.rust-lang.org/nightly/std/ffi/os_str/struct.OsStr.html "struct std::ffi::os_str::OsStr") stores these strings internally, which is undocumented. For instance, the result of calling [`OsStr::len`](https://doc.rust-lang.org/nightly/std/ffi/os_str/struct.OsStr.html#method.len "method std::ffi::os_str::OsStr::len") will not necessarily match the number of bytes this crate uses to represent the same string. However, unlike the encoding used by [`OsStr`](https://doc.rust-lang.org/nightly/std/ffi/os_str/struct.OsStr.html "struct std::ffi::os_str::OsStr"), the encoding used by this crate can be validated safely using the following methods:

- [`OsStrBytes::assert_from_raw_bytes`](trait.OsStrBytes.html#tymethod.assert_from_raw_bytes "associated function os_str_bytes::OsStrBytes::assert_from_raw_bytes")

- [`RawOsStr::assert_cow_from_raw_bytes`](struct.RawOsStr.html#method.assert_cow_from_raw_bytes "associated function os_str_bytes::RawOsStr::assert_cow_from_raw_bytes")

- [`RawOsString::assert_from_raw_vec`](struct.RawOsString.html#method.assert_from_raw_vec "associated function os_str_bytes::RawOsString::assert_from_raw_vec")

Concatenation may yield unexpected results without a UTF-8 separator. If two platform strings need to be concatenated, the only safe way to do so is using [`OsString::push`](https://doc.rust-lang.org/nightly/std/ffi/os_str/struct.OsString.html#method.push "method std::ffi::os_str::OsString::push"). This limitation also makes it undesirable to use the bytes in interchange.

Since this encoding can change between versions and platforms, it should not be used for storage. The standard library provides implementations of [`OsStrExt`](https://doc.rust-lang.org/nightly/std/os/unix/ffi/os_str/trait.OsStrExt.html "trait std::os::unix::ffi::os_str::OsStrExt") and [`OsStringExt`](https://doc.rust-lang.org/nightly/std/os/unix/ffi/os_str/trait.OsStringExt.html "trait std::os::unix::ffi::os_str::OsStringExt") for various platforms, which should be preferred for that use case.

## [§](#examples)Examples

```
use std::env;
use std::fs;

use os_str_bytes::OsStrBytesExt;

for file in env::args_os().skip(1) {
    if !file.starts_with('-') {
        let string = "Hello, world!";
        fs::write(&file, string)?;
        assert_eq!(string, fs::read_to_string(file)?);
    }
}
```
